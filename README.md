# 地産地消・必要量でつながる野菜仕入れアプリ

関西の農家さんと飲食店を、「必要な量だけ」でつなぐ野菜の仕入れアプリです。
課題資料 ISSUE E「関西の『地産地消』をAIで繋ぐ」をもとに作りました。

> 詳しい仕様は [docs/01_spec.md](docs/01_spec.md) にあります。
> 登場する人物・お店・データは、すべて作り物です。

---

## 1. 何を作ったか

農家さんが「売りたい野菜」を出品し、お店が「必要な量だけ」申し込むアプリです。
どのお店にどれだけ売るかは、農家さんが自分で決めます。

**お店（購入者）ができること**

- 食材名で出品を探す。量・使う日・予算（送料込み）・受け取り方法で絞り込める
- 必要な量だけ申し込む。農家さんの返事を、注文の一覧で回答期限と一緒に確かめられる
- 欲しい野菜が買えなかったときに、AI に「代わりの野菜」とその理由を提案してもらう
- 営業後に、余った量をボタンで記録する（使い切った／1/4／半分／3/4 余った）。ロスの量と金額をアプリが計算する

**農家さん（生産者）ができること**

- 値段・量・出荷できる日を決めて出品する。前回の出品の内容を使い回せる
- 届いた申し込みに「売る」「量を変える」「見送る」で返事をする
- アプリの中の取引記録から計算した相場と、お店がよく申し込む量を、値段や注文の単位を決める参考にする

**取引の流れ**

申し込み → 農家さんの返事待ち（申し込んだ量を仮押さえ）→ 販売確定／見送り／取消／期限切れ

- 回答期限は最長3日。期限を過ぎると自動で期限切れになり、仮押さえしていた量が戻る
- 農家さんが量を減らして返事したときは、お店がもう一度同意してから販売確定になる
- やり取りは、注文ごとのアプリ内メッセージで行う

**作っていないもの**：アプリの中でのお金の支払い、配送の手配や追跡、自動での購入

**使った技術**：Next.js（App Router）／TypeScript／Prisma 7／Neon（PostgreSQL）／Better Auth／Zod／Gemini API／Vercel

## 2. なぜ作ったか

**飲食店の三上さん**（大阪・福島の小料理屋）

- 週2回、朝5時から市場へ仕入れに行っている。狙っていた京野菜を大きな料亭に先に押さえられ、献立を組み直すことがある
- 使い切れなかった野菜を、毎週同じくらい捨てている
- 小規模な農家さんから直接買いたいが、つながる方法がない

**農家の坂田さん**（京都府南丹市で賀茂茄子を作る若手農家）

- 市場に出荷すると、値段は仲卸が決める。そのため、手元には限られた金額しか残らない
- 直接届けたいお店はあるが、つながり方が分からない

このアプリでは、三上さんは**市場へ行く前に**、必要な野菜を必要な量だけ確保できます。坂田さんは**自分で値段を決めて**出品し、どのお店に売るかを自分で選べます。

## 3. 工夫した点

### 売りすぎない・約束を守る

- **同時に申し込まれても売りすぎない**：残り1kgに2つのお店が同時に申し込んでも、アプリが1件ずつ順番に処理します。受け付けるのは先に処理された1件だけです。在庫の確認と書き込みは、1つのトランザクション（途中で失敗したら全部なかったことにする仕組み）の中で行います。
- **ボタンを何回押しても、申し込みは1件**：押した直後にボタンを押せなくし、サーバー側でも同じ申し込みを見分けます。
- **金額はアプリが計算する**：「単価 × 量 ＋ 送料」をサーバー側で計算します。画面から送られてきた金額は使いません。金額は円、量は g の整数で扱い、計算のずれを防ぎます。
- **販売確定のあとの取消は回数として記録し、取引相手に見せる**：理由に関係なく、取り消した人の回数に数えます。星の評価やレビューは付けません。始めたばかりの人が不利にならないようにするためです。

### AI は「提案するだけ」

- 値段・在庫・並び順・売買の決定には、AI を使いません。AI の役割は、代わりの野菜の名前と理由を提案することだけです。
- 代わりの野菜は「関西の野菜」で「予定していた料理に使えるもの」に限ります（例：万願寺唐辛子の代わりに伏見甘長とうがらし）。
- AI の答えは決まった形式かどうかを確かめます。形式が違えば、提案は表示せず、出品の一覧だけを見せます。そのため、「値段を0円にして」と入力されても、値段は変わりません。
- アプリで買えなかったときは、提案された野菜を「市場で探す候補」として表示します。三上さんは、何を探すかが分かった状態で市場へ行けます。

### 公平に並べる・個人の情報を守る

- 並び順は、新しい順・値段が安い順・出荷が早い順から、お店が選びます。人気順、名前順、お金を払った農家さんを上に出す表示はありません。
- 住所は、販売確定した相手にだけ、受け渡しに必要な分を見せます。それまでは「産地（市町村）」や「地域とお店の種類」だけを見せます。

### 食品ロスを減らす

- **ロスの記録はボタンだけ**：営業後の疲れていそうな時間（仮説）でも続けやすいように、数字は打たずにボタンを押すだけにしました。仕入れ量はアプリがすでに知っているので、入力しなくて済みます。
- **ロス金額と、前回との差を見せる**：「前回より ↓400円」のように、記録すると得をしたことが分かるようにしました。差は「ロスの量の差 × 今回の単価」で計算します。野菜の値段が下がっただけで「減った」と見えないようにするためです。
- **申し込むときに、前回のロスを知らせる**：同じ農家さんの同じ野菜で前回余っていたら、「前回（10/15）は 3kg で、半分余りました」と事実だけを表示します。申し込みは止めません。何kg申し込むかは三上さんが決めます。

### 使いやすさ

- お店が最初に入力するのは食材名だけです。ほかの条件は、必要なときだけ絞り込みで指定します。
- 一覧では、1kgあたりの値段（送料抜き）を大きく表示します。送料込みの値段はその下に並べて、比べやすくしました。
- 出品で毎回入力するのは、量・値段・出荷できる日の3つだけです。畑仕事の合間に、スマホでもさっと出品できるようにしました。
- 農家さんの申し込み一覧の下には、申し込みの合計と「全部売った場合の残りの量」を表示します。どれくらい売れ残りそうかが分かります。
- 選べる府県は関西の2府4県だけにして、「関西限定」と分かるようにしました。
